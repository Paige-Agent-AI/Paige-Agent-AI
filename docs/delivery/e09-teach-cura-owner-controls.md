# Teach CURA — original Knowledge, owner-controlled sharing

## Bounded owner outcome

Inside the existing Clients → Portal → Experience tab, an authorized publisher
can inspect original business Knowledge, resume/correct a source in the existing
AddKnowledgeFlow, publish it privately, then review an explicit customer-sharing
decision. A private publication never automatically becomes customer material.
This is the same EXP09 Portal; no new shell, Knowledge store, model runtime,
customer history, permission system, approval channel or sender is introduced.

The owner chooses FAQ/approved answer, service information, offer/price,
promotion, campaign information or policy/terms, plus UTC effective/expiry dates.
Review binds the native source version/fingerprint, business audience, dates and
proposal hash. The original K1 writer requires its native publisher predicate and
expected share revision. An interrupted response is recovered through its exact
operation/receipt, never an automatic second write. Withdrawal ends future use
through this business-wide share; separately assigned customer Resources remain
under their original controls. Existing private conversation history is retained.

## Canonical action-to-record path

| Owner interaction | Existing authority/record | Result and reload |
| --- | --- | --- |
| Inspect/search/paginate | `read_client_portal_business_knowledge`, original docs/share state | Closed, current tenant DTO; error is not an empty result |
| Resume draft | Original extraction review + `read_tenant_knowledge_pending` | Exact tenant/document/revision/work and staged metadata; no second extraction |
| Add/correct privately | Original AddKnowledgeFlow/Knowledge extraction, review and publication | Existing durable work, revision and publication readback |
| Review customer use | `prepare_client_portal_business_knowledge_share` | Source/version, preview, audience, kind, exact validity window/proposal hash |
| Approve or withdraw | `set_client_portal_business_knowledge_share` | Original operation UUID and atomic native receipt/share revision |
| Recover interruption | Exact document read and original receipt/terms comparison | No retry or success inferred from generic availability |
| Switch business/account | Actual context/actor incarnation plus native authorization | Old content/results retire; A→B→A cannot revive a stale response |
