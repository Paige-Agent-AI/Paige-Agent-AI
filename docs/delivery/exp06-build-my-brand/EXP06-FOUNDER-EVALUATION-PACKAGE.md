## 2a. THE WALKTHROUGH SCRIPT (owner-facing; ~30 minutes; run in your own signed-in account)

> Plain-English click-by-click. Say whatever you actually think at each step — reactions
> ARE the findings. Anything you flag becomes the repair list; nothing is pre-graded.

**Set-up (1 min):** sign in to your own workspace at paigeagent.ai. You'll use YOUR
business's brand, so everything you see is real.

1. **Your brand (3 min).** Open Marketing → Vibe Studio ("Build my brand"). At the top
   of the chat you should see it working FROM your brand (name/colors/logo if set —
   or an honest "nothing set yet" if not). ✎ *Does it feel like it knows your business?*

2. **Make a page (5 min).** Ask Paige to build you a landing page (e.g. "make a page
   for my weekend workshop"). Watch it draft; open the preview. Try phone width if handy.
   ✎ *Would you show this to a customer?*

3. **Go live (3 min).** Click Publish. Read the approval card — it names the page, the
   FULL web address, and says anyone with the link can open it. Approve it. Open the
   address. ✎ *Is the card honest? Is the page what you approved?*

4. **What Google shows (2 min).** In the publish panel, read the sharing preview —
   "What search and share will show" — including its honest caveat about previews that
   never load the page. ✎ *Is anything overpromised?*

5. **Take it with you (2 min).** Use the export/download in the panel. You get a real
   static file of exactly the published page. ✎ *Is the file what you expected?*

6. **Your own address + hosting (4 min).** Open "Use my own address" in the panel.
   Read the current state, pick where your domain lives (the six providers), see the
   mail-records promise. At the host path, click **"Check hosting for this page."**
   Today it answers: *"Hosting isn't switched on yet. Nothing was changed."*
   ✎ *Is that the right thing to say? (Turning it on is your call, later, whenever.)*

7. **Publish from the TEAM HUB (5 min) — the step that closes the both-chats proof.**
   Open your Team Hub. In a channel or your DM with PAIGE/NEXUS, ask to publish the
   page (or use the card). The SAME approval card appears — approve it there.
   ✎ *Same experience both places? This click is the authenticated Team Hub proof the
   records still owe.*

8. **Take it down, put it back (3 min).** Unpublish from either place; watch the honest
   states (what stays live, what doesn't). Republish if you like. ✎ *Anything scary?*

9. **Last look (2 min).** Anything in the whole flow that confused you, looked wrong,
   or felt like it lied? That's the list. Done.

**Findings capture (per the roster doctrine):** reactions are recorded as Functional /
Visual / Experiential only — identity and branding alone promote nothing. Each finding
becomes repair work on this lane under the same gates; the Experience closes only on
what this walk actually proves.

## 2. The walk (the integrated journey to evaluate)

1. **Brand → site.** Enter the Studio from a project; the brand context line shows the
   workspace's confirmed brand facts (or the honest missing state). Design a page through
   Paige; the publish panel prepares through the ONE door (checks, fingerprint, address).
2. **Before going live.** The panel shows what search and share will say (title +
   description, or the honest "no description set — ask Paige"); "Use my own address"
   explains domains truthfully (reserved address never called live; the six providers;
   mail records never touched; the owner-gated host path with honest costs).
3. **Go live.** Publish → "It's live" with the proven address; the page renders the
   PUBLISHED version with the owner's brand floor; the browser tab and a shared link
   carry the page's own title/description/image; a visitor submitting the consented form
   is linked to the visit that brought them (source: paige_form).
4. **Revise & recover.** Change the draft — visitors keep seeing the published version;
   "Put your changes live?" re-publishes through the same door; unpublish/restore/republish
   keep canonical identity; a stale or role-changed approval dies with a fresh prepare and
   an exact explanation, never a blind retry; a downloaded export is a copy, never a move.
5. **Quality.** Responsive at the Solo viewports; keyboard-operable disclosure/select/
   forms; reduced-motion honored; media says when it cannot be shown; nothing anywhere
   claims ranking or a live address that was never verified.
