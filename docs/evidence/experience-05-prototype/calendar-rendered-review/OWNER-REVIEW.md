# Weekly Internal Commitment Check — Chat + Calendar owner review

This is a rendered, deterministic review prototype. Chat proposes and authorizes the weekly internal check; Calendar reads the same process and shows actual next-run instants. No real schedule, appointment, permission, execution or communication is created.

[Open the self-contained local review HTML](../../../prototypes/weekly-commitment-check.html). GitHub previews the PNG gallery below; download the HTML for local interaction. The review controls and approval notes are local simulation, not an owner ruling or production authorization.

## Review route

1. Request the check in Chat, review owner-personal Planning scope, Monday 09:00 and configured America/New_York, then authorize the exact process revision.
2. Inspect pending/readback and default-confirm holds. A saved authorization does not grant auto tool permission or lift a separate platform trigger hold. Actual next is null while held; an intended slot is labelled separately.
3. Compare the same process reference/revision in Chat and Calendar. Calendar markers are points, with no appointment, duration, time reservation or availability effect.
4. Inspect a running attempt, receipt-confirmed result, failed result and unknown latest attempt with an older verified result. Unknown remains unknown after absence readback; no owner replay is offered.
5. Pause, edit, resume or cancel via Calendar’s handoff to the same Chat exact-revision confirmation. Changes appear in both views only after authoritative readback. Pause/cancel affect future runs; a running act remains running.
6. Read later-conversation status and check stale/refused, unavailable and lost-response recovery. Check display-zone changes, missing/invalid zones, DST, off-hours dates and mobile context.

## Accessibility evidence and limits

Measured current checks cover visible control labels, resolved ARIA references, unique ids, Tab-reachable confirmation, safe cancel-dialog initial focus and Escape return, current-thread semantics and mobile conversation focus, reduced motion and 320 CSS-pixel reflow. Input text contrast samples are 17.89:1 Mineral / 15.81:1 Obsidian; boundary samples are 6.41:1 / 6.99:1. These are sampled controls, not a broad WCAG claim.

The four SOLO desktop widths are 1536, 1366, 1024 and 900, with PAIGE closed/open; mobile is 390 and reflow is 320 CSS pixels. One offline retained-proposal frame deliberately uses a 390×1000 viewport so fields, error and recovery remain visible together; the manifest records every actual viewport. The 390×843 capture document is 844 pixels high. Compact mobile Week labels remain dense; Agenda provides readable detail. Assistive-technology acceptance, browser 200% zoom, the mounted authenticated shell, Live and native haptics remain UNVERIFIED.

No background-focus-escape or native browser-chrome behavior claim is inferred from the old dialog wrap assertions. The old 114/116 failure history and repaired old 130/44 packet are preserved as historical evidence on different artifact hashes; neither is current proof.
