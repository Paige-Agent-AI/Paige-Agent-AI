# Weekly check across Chat and Calendar — prototype contract

Goal: One owner authorizes a bounded weekly internal check in Chat and recognizes the same process, schedule revision, execution and verified result in Calendar.
Human and feel: Business owner; calm, accountable and clear about pending or held work.
Entry and exit: Existing PAIGE conversation or Clients → Calendar; Calendar controls return to the same Chat context for exact-revision confirmation.
System: Incumbent SOLO Mineral/Obsidian tokens, repaired accessible conversation controls, existing Calendar week/agenda/inspector vocabulary and explicit internal scroll owners.
Signature: The same process reference and revision stay visible across Chat, Calendar and later conversations; changes appear only after authoritative readback.
Feedback: One bounded 150ms result update; immediate under reduced motion. Native haptics remain UNVERIFIED.
Rejecting: A new automation dashboard, a second scheduler/ledger, booking-shaped automation, optimistic success or replay of an unknown execution.
Variants: Owner/member and neutral local workspaces; four SOLO desktop viewports with proposed PAIGE closed/open, mobile/reflow and keyboard. Actual authenticated source-shell acceptance remains UNVERIFIED.

OWNER_INTENT: Present an interactive, locally simulated owner review of canonical Calendar + Chat in one Experience 05 flow, with remotely usable repository-relative rendered screenshots. Chat owns recurring-work proposal, authorization and controls. Calendar is a visibility projection.

MUST_NOT_HAPPEN: No appointment, calendar, booking or event write; no time reservation; no UTC recurrence invented; no provider/model call, live activation, production UI mount, second record or unknown replay; no historical130/44 proof represented as current; no authority inferred from the local decision button or finish verdict.

MUST_PRESERVE: Owner-personal Planning scope, separate default-confirm Settings permission, platform trigger-dark holds, future-only pause/cancel, current-revision readback, receipt-confirmed completion, last verified result independent from last attempt, same conversation memory, incumbent styling and prior accessible evidence unchanged.

ACCEPTANCE_CRITERIA: Review both surfaces from empty through request/authorization, pending/readback, held and active schedule, running/completed/failed/unknown, inspected receipts, exact-revision pause/edit/resume/cancel, readback failures/stale/refused controls and later Chat+Calendar status. Render and drive the states at desktop/mobile; authenticate separately before any customer outcome claim.

## States and transitions

| --- | --- | --- | --- |

| Pending | Simulated canonical acceptance | Awaiting authoritative readback | Both views retain prior confirmed snapshot; read saved process |
| Readback pending | Same process/current revision confirmed | Held or scheduled | Both surfaces adopt one snapshot atomically |
| Saved | Default confirm/off or platform trigger dark | Held, actual next null | Intended slot separately labelled; Settings cannot lift platform hold |
| Scheduled | Governed simulation claims due run | Running | Instant Calendar execution marker, no duration or reservation |
| Running | Observation and receipt confirm completion | Completed | Result, receipt and last verified execution shared |
| Running | Uncertain or failed read | Unknown/failed | No owner replay; authoritative absence remains unknown |
| Any confirmed process | Calendar control | Chat confirmation for same id/revision | Read-only handoff, no mutation before owner confirmation |
| Confirmed process | Owner confirms pause/edit/resume/cancel | Pending/readback | Future-only; running act remains; cancel consequence dialog |
| Stale handoff | Revision differs or service refuses | Refused/unconfirmed | Preserve prior state; refresh, review and confirm current revision |
| Later conversation | Read same confirmed process | Last attempt/last verified/next status | Same reference; no inferred success |
| Wrong role/workspace | Read/control attempted | Owner refusal/cleared context | No other workspace snapshot shown |
