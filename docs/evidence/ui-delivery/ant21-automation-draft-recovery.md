## Root cause and bounded repair

The existing Chat automation_draft silently sliced21 or more steps to20 and truncated names/categories after approval. It claimed a process was built from successful insert responses without independently reopening the process/acts. Its compensation deleted by id alone and treated an empty successful deletion as proof that nothing existed. A lost creation response invited another name; a lost steps response could delete a successfully committed draft. The autonomy lookup defaulted to confirm even when readiness could not be read.

Keep the incumbent caller-JWT paige_automations and paige_automation_acts writers. Validate supported exact inputs before either write, enforce the server workspace equality precondition, and require a native process UUID/revision. A definite single-statement acts refusal may compensate only the same newly created, unchanged draft using tenant/id/creator/state/grant/original revision predicates. Only the exact returned deleted row proves compensation. A lost response, concurrent revision or zero-row cleanup remains uncertain. Unknown acts writes are reopened rather than retried or deleted.

Successful configuration requires independently reopened exact process fields and ordered acts, semantic JSON configuration equality, a stable final parent revision and current workspace. The existing database acts-fingerprint trigger legitimately changes the parent revision after steps are inserted; success does not mistake that for an intervening edit. A readiness response failure does not erase verified saved-configuration evidence. It reports readiness unverified and no actual execution. New closed automation receipt references and native-only attribution preserve an inspectable identity without copying model arguments or granting replay authority. The existing request and persisted-unknown successor brakes are reused.

This is not an executor replacement. Native orchestrator/decide/approval/act-execution and event dispatch remain the only automation execution pathway. State remains draft and grant confirm, even when an operator asks for autonomy in the same request. Owner-only grant/state policy, action-risk, Harness/Spine/Trust approval, native RLS, provider requirements and INT-346 admission are unchanged. No native process, event, execution or provider call is made in production by this change.
