## Canonical implementation

The new required five-argument `list_team_bookings` overload contains the incumbent native authorization and full 24-field projection. A separate static exact-ID branch places `b.id = _booking_id` inside its query before PL/pgSQL materialization; NULL preserves the legacy listing branch. The original four-argument signature retains its OID, argument defaults, owner, language, STABLE/SECURITY DEFINER, search path, return shape and explicit ACL, and delegates with NULL. The fifth argument has no default, avoiding ambiguity for two-, three- and four-argument callers. The original `_host_ids` spelling is retained. No role, account, class/session or writer semantics are expanded.

The adapter accepts only `{ booking_id }`, captures the server-provided `ContextIdentity`, requires ordinary SOLO context, verifies the original caller's user/current tenant before and after the read, and rechecks canonical native membership/admin visibility. It uses the original caller-JWT RPC with the exact five named arguments, finite selected fields, outer `.eq(id)` and `.limit(2)`, an installed transport abort signal and one overall eight-second deadline across every await. It never reads a booking table or guest/profile record independently. Notes, intake answers, provider payloads and URLs are excluded. Unknown, malformed, duplicate and late scope data cannot become found/not-found success. No error path retries an action or the reader.
