## Existing freshness seam reused

The hook already keys list reads by `tenant-relationships/people/<activeTenantId>/<mode>` and
detail reads by `tenant-relationships/person/<activeTenantId>/<contactId>`, with `staleTime=30_000`.
It still exposes `retryPeople` and `retryDeepLink`; the People editor's `handleSaved` still awaits
both. The new bounded helper uses the SAME provider QueryClient and exact existing list/detail
keys. It cancels those queries, marks them stale without refetching, then invalidates active
observers after the await, so an initial pre-turn read cannot satisfy the new readback through
an older shared promise. A retired view leaves a stale cache for a future mount. Mounted generation and current
tenant/mode identity are checked after cancellation awaits. A same-tenant detail selection change
does not drop the list refresh; an inactive captured detail is marked stale without an unrelated read.

Only mounted SOLO People consumes the existing `paige:turn-settled` window event. It means read
again even after uncertain/error turns, never business success or approval. Open editors coalesce
signals until close, and the existing editor snapshot stays mounted even when a previously started
background read fails. Draft text, focus and explicit close behavior are retained. Closed read
failures keep the existing error presentation; no new label, banner or geometry is introduced.
Account-keyed component ownership drops old deferred editor work; hook lifetime/scope fences stop
awaited old refresh work. Hidden People and the non-SOLO roster do not subscribe. Listener cleanup,
initial read races, read errors, tenant switches, unmount and editor behavior are exercised through
the existing test suites. Native readback after an actual released Chat mutation remains UNVERIFIED.
