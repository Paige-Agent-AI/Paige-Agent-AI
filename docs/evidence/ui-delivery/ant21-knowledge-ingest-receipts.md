## Root cause and bounded correction

The existing Chat action invokes `kb-ingest-doc`, whose shared core verifies the private document,
indexed chunk rows and reconciled count. Neither that native executor nor the core filed a
`record_capability_run` receipt for ingestion. The separate caller-JWT `paige_audit_log` projection
is not a workspace Rail receipt. Adding a generic recorder at Chat dispatch would use the wrong
authority, miss a native save whose HTTP acknowledgement is lost, and risk duplicating other
capabilities' executor-owned receipts.

The native executor now records after verified core persistence and its existing caller-scope
check, using its existing admin client and the canonical `recordCapabilityRun`/`stableRunId`
helpers. The key derives from capability, tenant and saved document ID; detail contains only
document identity, chunk count, indexing completeness and operation. The document body and title
are excluded. A post-recording scope check prevents exposure of the former workspace's result.
The existing core, database, providers and metadata/delete executors are unchanged.

`ok` remains native ingestion truth for incumbent callers. A recorder error cannot remove or
re-ingest an already verified document. The Chat consumer validates any new receipt envelope
against its server-selected tenant and exact result shape; a missing envelope remains compatible
with older native responses without fabricating receipt evidence. Contradictory envelopes and
unknown writes retain the existing reconciliation brake. Partial indexing stays partial even if
the receipt succeeded. Conversely, a receipt acknowledgement can fail after its row committed;
the existing `capability_completed_unrecorded` projection therefore says activity evidence
"could not be confirmed," rather than asserting that a row is absent.

The existing opt-in Knowledge outcome contract now covers this save in the approval card,
model normalization and interactive effect. A verified completed save has a successful business
effect with an unconfirmed-activity caveat, not a falsely failed action. The separate existing
audit projection retains `completed_unrecorded`; no receipt writer was added to that hook. Other
capabilities keep their existing failure/uncertainty handling. Document-ID receipt deduplication
does not provide request-level ingestion idempotency: an explicit new save can still create a
new document. No automatic retry or ingestion exactly-once claim is introduced.
