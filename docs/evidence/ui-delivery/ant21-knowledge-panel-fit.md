## Cause, scope and capability routing

The original Knowledge grid always used `minmax(0,1fr) 300px` and only stacked under a 980px **viewport** media query. At 1514x774, the native dock measured 513.75px. After scroll padding and gap, its source track was 151.75px; a normal source card's intrinsic 207.31px width extended 41.56px under the300px Mind aside. This reproduced the supplied defect in the real component. A horizontal-overflow assertion alone missed the sibling intersection. The failing-first drive with original CSS also catches long unbroken source text escaping the track.

The repair names the Knowledge panel as an inline-size container. The grid defaults to one `minmax(0,1fr)` track, returning to the existing source+300px-aside layout only at 780px of **panel** width (at least 418px for the source after the existing 48px padding and 14px gap). Below 640px, the existing narrow header/provenance arrangement follows that same container. Knowledge-only minimum-size/wrap rules keep intrinsic grid content and long provenance inside their cards. No overflow suppression or new scroll region is added. Container-query fallback remains the safe single column.

The existing Settings evidence mount had hardcoded controlled `dockedTab="chat"` with a no-op change handler. Its tiny local-state correction now mirrors the native owner so the existing Knowledge tab can actually be selected in this harness. The browser drive modifies only that harness's existing synthetic Supabase module **in memory**, supplies neutral rows through the real Knowledge hook/service, and blocks requests outside loopback. It creates no parallel component, store or authority. The production TSX component is unchanged.

Routing answers: owner outcome=read/review unobscured Knowledge; domain=Chat/Command Center presentation over the existing Knowledge owner; Harness A/B/F=current existing contracts unchanged (completion map remains PARTIAL, no replacement); Spine=`knowledge.read` via `read_tenant_knowledge`, no registration change; provider=internal canonical Knowledge, no connection/spend added; risk/lane=read_only with no approval or MUTATION_VERB; durable events/jobs=none; readback/receipt=existing read projection, no effect or new receipt; surface=SoloPaigeWorkspace Knowledge, linked Mind destination remains the ledger's existing `command-center.mind` state with no promotion; authenticated proof=ordinary deployed source/provenance/Mind/fold drive remains UNVERIFIED.
