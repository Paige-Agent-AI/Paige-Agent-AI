# UI delivery evidence: purchased numbers ring, and a call that did not connect says why

Branch `worktree-agent-ad25c86756c37c6bc` from origin/main `4fb4b0398`. Commits `86097a38f` (voice wiring at purchase, honest call-outcome wording) and `4eda3b900` (review M1: inbound outcome robust to callback order, plus three minors). Edge functions and shared copy maps, plus one copy case in one UI file (`src/components/admin/comms/NumbersTab.tsx`). No layout, token, motion or component change.

What a person sees change:

- **A number bought in the marketplace takes calls.** Purchase now sets the number's voice webhook (`VoiceUrl` + POST) with the same helper the voice repair uses, so an inbound call rings the business's seats. Before, the number was bought SMS-only and inbound calls went nowhere. This only affects numbers bought after deploy.
- **Clients → Conversations, a call row that did not connect** keeps its "Failed" pill. The line under it now says what happened:
  - "No answer."
  - "The line was busy."
  - "The call was cancelled."
  - "The provider rejected this call." only for a real provider failure.
- **An inbound call answered by one of several seats reads Completed, with that seat's talk time.** A missed inbound call reads Failed · "No answer.". Neither depends on the order the provider's callbacks arrive in.
- **The dialer's error line** says "No answer." or "The line was busy." when the person called doesn't pick up, is busy or declines. Before, it said "The provider rejected this call. Check the number and retry."
- **Buying a number when calling isn't set up** now reads "Your business isn't set up to buy numbers yet…" on the Numbers tab, and "Calling isn't finished being set up… Nothing was bought." on Solo settings. Paige reports it as a refusal. Before, it read "Try another — this one may have just been taken." and Paige reported "outcome unknown".
