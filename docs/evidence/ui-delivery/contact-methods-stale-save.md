## Review and limitations

Independent review (§39) by a separate instance that did not write this code, on the pushed diff at 200e6cb: FIX-FIRST. Every finding is fixed in this PR or named here.

- (medium, confirmed) A value stored with a trailing no-break space made every save of that person's list stale, forever: the browser trimmed it and the database did not. Fixed twice over — the loaded list is sent exactly as read, and the comparison ignores outer whitespace on both sides.
- (low-medium) Paige's MCP update_contact replaced a list with no check. Fixed: it requires expected_contact_methods and replaces through _replace_client_contact_methods_checked.
- (low) clients.updated_at is coarse: a logged message or enrichment would refuse an address save, and the rebase then drops the person's relabels. Fixed by comparing the list itself for these saves.
- (low) A second Save after a successful one sent the old basis and was refused as stale. Fixed: the basis moves to what was saved.
- (low) During a deploy, a page older than the server showed PostgREST's "Could not find the function" text. Fixed: both editors say the page is out of date.
- (info) The stale message was announced twice. Fixed.
- (info) The local database it inspected lacked the trigger (left by an earlier mutation run). Every figure above comes from a database rebuilt from scratch.
- (info, owner-ruled) An owner or admin editing the workspace owner changes a list that is global to that person and feeds notification delivery. Raised with the owner alongside the security-alert routing question; not changed here.
