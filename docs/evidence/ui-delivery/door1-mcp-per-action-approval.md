## What this changed, and the defect that shaped it

The first cut rendered "You approved this" from the read's `approved` flag. That flag means only
that an approval row exists, while `verify_mcp_connection_approval` — the function that decides at
dispatch — refuses on seven conditions. The read modelled two. An approval bound to an endpoint the
connection no longer uses, or bound to no endpoint at all, therefore came back unexpired and
unstale, and the surface told its owner they were covered over consent the runner would decline,
with no control on that row to fix it because nothing looked wrong.

The read now computes `approval_blocked_reason` for the five conditions a catalogue can see, in the
verifier's own order, so the reason it gives is the reason the runner would give. Two are
deliberately not modelled: one compares the approval against the endpoint a runner actually loaded
for a specific dispatch, the other against the arguments of a specific call. A null is therefore
never a promise that a run will succeed, only that nothing visible from a list blocks it.

## Review and limitations

The SQL test had never been executed. Run against Postgres for the first time it failed three
times before it passed — `tenants.slug` is NOT NULL, a trigger refuses an already-expired approval
so that fixture could not be inserted through the front door, and `_mcp_endpoint_hash` is revoked
from `authenticated` so an assertion could not call it after impersonating a member. That last one
is the revoke working as designed. Its connections also carried no endpoint at all, which means
every "live approval" assertion in it was passing over consent the runner would have refused: the
same defect as above, sitting inside the test written to catch it.

Both test doubles were lying in the same way. The unit file served one resolved value to every edge
action, so a tools call received a connection-shaped body, the hook found no array where it
expected one, and the drawer rendered its degraded branch in all 52 tests that open a drawer, all
of them green. The render harness had the same hole. Both now dispatch on what was actually asked
and fail loudly on anything unstubbed.

Observed and not absorbed: the shared primary-button treatment tints gold at 15%, which reads as
very quiet in both themes — on an approve control, the most literal act moment on the platform, the
accent barely registers. It is left alone deliberately, because the same class carries Add, Save
and Confirm across the whole Integrations surface and retuning it here would change shipped controls
this task never touched. Raised rather than changed.

Also observed: the page behind an open drawer keeps its own scroller, so two scroll owners exist
while a drawer is open. That is pre-existing drawer behaviour, not introduced here, and the
measurement above is scoped to inside the drawer, which is what this change owns.
