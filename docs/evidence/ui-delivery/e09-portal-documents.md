## §58 call-outs

- The customer list no longer shows a `client_upload` row uploaded by a different login of the same client (the old "Customer upload" label); the server read returns only the caller's own uploads (plan 1e). Production has 0 `client_files` rows.
- The customer Home Documents tile no longer counts the legacy `documents` table (0 production rows) and no longer opens `/app/business`; it opens `/app/documents`.
- The customer preview no longer builds a Blob URL; it uses one-minute signed links.
- The static "Client files · PARTIAL" record card and the Portal "Files and agreements" card text change to point at the live section.
- The unreachable admin `ContactFilesPanel` upload stops working (backend fold-in 1g.2, D5); the panel is not deleted.
- Round 2, backend (commit 5bd8f8700) — tightenings, called out so they are not silent: a file moved to another client now arrives PRIVATE on every writer (before, a move kept it shared and silently re-shared it with the new client, with no share audit row); a signed-in, non-service write that moves a file into or out of shared outside `client_file_set_client_share` is refused (`FILE_SHARE_WRITER_REQUIRED`), so a REST share by a member holding the global admin role, or Paige's re-file with a description, now goes through the one share writer; a platform admin in a company workspace is refused at `client_file_owner_begin_upload` instead of being left with a reserved row it could never fill. Already-shared rows are backfilled `shared_at = updated_at` with `shared_by` NULL; both parsers accept that row and neither requires the sharer.
- Round 2, frontend: the Operations Delivery "Client outcome" line now reads "Acceptance unavailable" for a sub-account, agency or enterprise and "Releasing needs a second reviewer on your team" for a one-member standalone business, where round 1 said "Recorded on each work item in the project" for any linked project. The release flow's selects are named by their visible labels ("Studio session", "Saved work", "Version", "Reviewer"; previously aria-labels "Studio session", "Saved artifact", "Artifact version", "Independent reviewer"). For a one-member team the review section no longer renders when nothing is recorded.

## Known limits

- Sub-account and Enterprise businesses can upload and share through the server but have no screen (§60 gap, same as Slice 3).
- Releases need a second active team member and a standalone business (D2/D3); file artifacts cannot be released.
- No owner delete or rename (D7); the customer cannot delete or rename (D8).
- The customer list pages by `created_at`; two files with the identical timestamp at a page boundary could be skipped by "Load more".
- The owner list shows the newest 100 files and says older files can't be listed yet: "Load more" (compliance S5) is not built because `client_file_owner_list` has no page cursor, and a button there would be a dead control. Owed: a keyset cursor (`created_at`, `id`) on that read, then the customer page's pattern.
- The Operations release flow keeps its native selects, like the rest of Operations (the Work filter, the CRM stage review); a shared select primitive across Operations is its own change.
