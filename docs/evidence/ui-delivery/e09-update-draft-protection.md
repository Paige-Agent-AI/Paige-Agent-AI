## Prototype brief and state map

Goal: complete a message safely while an update is available.
Human and feel: customer/owner, calm uninterrupted work.
Entry and exit: existing composer or editor; finish/clear work, then optional explicit Reload or Dismiss.
System: same React banner/control/token system; local synthetic host only.
Signature: the update yields to work already in progress.
Feedback: unchanged notice and inline pending/error; no haptics.
Rejecting: a second notice or fixed overlay intercepting Send.
Variants: desktop and narrow; owner dock states only as geometry, not authenticated proof.

| From | Trigger | To | Recovery / exit |
|---|---|---|---|
| Idle/update available | Focus editable control | Notice hidden | Blur with empty work permits notice |
| Draft | Blur/Send | Draft or response pending, notice hidden | Existing native unload guard and explicit clear |
| Upload/reply pending | Finish | No active work, notice returns | Optional explicit Reload/Dismiss |
| Reply error/recovery | Retry | Pending, notice hidden | Clear work explicitly |
| Multiple editors | Clear one | Notice still hidden | Last guard clears notice returns |
| Clear | Explicit Reload | Original guarded reload only | No automatic reload |

Permission/server/offline outcomes of a message remain in the original Chat; this repair has no independent request or server path. Prototype uses deterministic local controls and no actual backend, file upload, communication or business action.
