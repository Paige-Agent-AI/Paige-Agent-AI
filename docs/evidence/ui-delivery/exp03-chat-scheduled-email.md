# UI delivery evidence: EXP03 — Paige's chat schedules a governed email; the approval card says When

Commit 025ff551 (feature). Two UI files change — `src/components/chat/PaigeConfirmCard.tsx` and `src/components/chat/confirmPreview.ts` — plus `src/pages/admin/conversations/governedSend.ts`, which now re-exports the moved `scheduledForLabel` (no behaviour change). The chat's shared email module (`supabase/functions/_shared/comms-email/chat.ts`) and the Kit declaration (`_shared/paige-spine/domains/comms.ts`) change the request contract Paige's chat sends to `comms-email-command`, declared `Visible-Flow-Impact: yes`. The door itself is unchanged.

What a person sees change in the PAIGE chat (Solo and Sub-account; the same card everywhere the chat mounts):

- **Asking Paige to email someone at a later time** ("send Maya the proposal Tuesday at 9am") now raises the normal Needs your OK card for that email with one more row under To / From / Subject / File(s): **When — "Sends Tue, Nov 3, 9:00 AM"** (weekday, month, day and time in the viewer's own clock; the time never splits across lines).
- **The act reads "Schedule send"** (clock icon) instead of "Approve" for a lone scheduled email. A batch of approvals keeps "Approve N"; the scheduled email's row still shows its When.
- **An email without a time is unchanged:** no When row, "Approve".
- **The chat's card now also lists the files** an email carries (name and size) when the door's preview has them — the chat used to drop them. (No chat path attaches files today; this keeps the card truthful if one does.)
- **After approval** Paige says it is scheduled and nothing has been sent yet; the email then waits in Conversations as Scheduled with its Cancel (piece 1, already live).
