# UI delivery evidence: EXP03 Resend retired — every remaining PAIGE email on SendGrid, and an unconfirmed send is never offered as a resend

PR #2966 (branch `claude/great-heisenberg-u7kyd9`). Follows #2958 (`exp03-sendgrid-platform-email.md`), which moved PAIGE's platform email; this PR moves everything that was still on Resend and retires it. It changes four UI files — three in the inbox, plus `src/components/dashboard/ContactSupport.tsx` from the review-fix commits — and declares `Visible-Flow-Impact: yes` for the backend.

What a person sees change:

- **Clients → Conversations inbox.** If SendGrid's answer to an email is lost (a 5xx or a timeout), the email may already be in the client's inbox. SendGrid cannot deduplicate a second POST, so sending it again could mean two copies. The inbox no longer shows that email as a plain red "Failed" with the raw `delivery_unconfirmed` code under it. It shows the existing amber pill **Couldn't confirm** and, in ink (never the failure colour), the line **"Couldn't confirm this went out — don't resend."** A definite provider refusal now reads as owner copy ("Not sent — that email address wasn't accepted. Check it and try again.") instead of the raw `sendgrid_400: {…}` text, and the Failed/Sent/Accepted/Delivered/Not sent pills are deepened toward ink so they pass AA in light.
- **Approve & send and the reply composer** now show a warning toast instead of an error: **"We couldn't confirm it was sent — it may already be with them. Don't send it again until you've asked them."** Before, the error toast left the Approve & send button on the draft card, so one more click would send a second copy. Now the draft row reloads as Couldn't confirm and no send button is left on it. The reply composer clears.
- **New-conversation dialog.** It shows the same warning, then closes and opens the thread. It does not leave a Send button behind.
- **Contact support form** (`ContactSupport.tsx`, added in the review fixes after 4e7af345). If send-support-request answers unconfirmed, the form shows a warning toast, "We couldn't confirm it reached our team", with "It may have — please don't send it again; email support@paigeagent.ai if you haven't heard back", and keeps what was typed. It does not show an error. This is covered by `ContactSupport.test.tsx` (3/3). It is NOT rendered by this record's harness.
- **Server backstop** (send-message, review fixes). A second send of a row already marked `delivery_unconfirmed`, for example from a stale tab's Approve, is refused before any provider call and answered unconfirmed again (`send-message/index.ts` ~L1046-1056).
- **Platform email arrives again.** These now send through SendGrid from `@mail.paigeagent.ai`: support-request confirmations, payment confirmations, welcome email, funding reports, skill-runner's emailed documents and paige-mcp's four send tools.

## User job and state map

The owner replies to and approves email to clients. The intended scroll owner is the thread column. The states are:

- **Sent:** success pill.
- **Failed:** a definitive SendGrid refusal. Red pill plus the reason line.
- **Couldn't confirm:** the answer was lost. Amber pill plus "Couldn't confirm this went out — don't resend." No send affordance stays on the row.
- **Draft:** Approve & send. If the answer is lost, a warning toast appears and the row reloads as Couldn't confirm.
- **Composer:** if the answer is lost, a warning toast appears and the composer clears.
- **New-conversation dialog:** if the answer is lost, a warning toast appears, the dialog closes and the thread opens.

## Review and limitations

**Impeccable craft findings — 1–4 FIXED in this PR after the first render (frames and numbers above are from the re-render).**

1. **FIXED — the don't-resend line was red under an amber pill.** `ClientsConversations.tsx:299` routes the line through the bubble's `error` prop. `MessageBubble.tsx:228` paints that prop `text-destructive`, measured as the destructive token: rgb(164,71,61) in light, rgb(237,160,146) in dark. So the one line meant to say "this is not a failure" is drawn in the failure colour, beside a warning pill. The governed path already renders the same line in ink through the `footer` slot (`ClientsConversations.tsx:327-330`, `text-foreground`). Proposed fix:
   - at :299, return `null` for an unconfirmed row instead of `GOVERNED_SEND_COPY.unconfirmed.line`;
   - at :327, widen the footer condition to `governed === "unconfirmed" || isUnconfirmedMessage(m)`.

   This also lifts the light line from 4.86:1 (passes AA, barely, at 11px) to ink contrast.
2. **FIXED (the proposed copy, adopted in the toast; the support form now says don't send it again too) — the toast and the line gave two different instructions, and the support form added a third.** The support form says "Please wait a few minutes before sending it again" (`ContactSupport.tsx`). The toast says "check before sending it again". The line says "don't resend". The owner has no in-product way to "check". Proposed copy for `SEND_UNCONFIRMED_COPY` in `inbox-shared.ts`: "We couldn't confirm it was sent — it may already be with them. Don't send it again until you've asked them." The alternative is to keep the toast and change the line to match it. One instruction, said once, either way.
3. **FIXED (`ownerSendError` in inbox-shared.ts; the raw code stays in the row) — a plain failure showed the raw provider string.** Example from the frames: `sendgrid_400: {"errors":[{"message":"Does not contain a valid address.",...}]}`. This passes through `m.error` (`ClientsConversations.tsx:299`) and puts a vendor name and JSON in the owner's view (§11 no backend names). It is not introduced by these UI lines. send-message's SendGrid arm writes `sendgrid_${status}: ${body}` (`send-message/index.ts` ~L449), and this PR routes more sends through it. Proposed fix: a small copy mapper in `inbox-shared.ts`. A 4xx maps to "The email service refused this address — check it and send again". Anything else maps to "The email service didn't accept it — try again." The raw code stays in the audit row.
4. **FIXED (PILL_INK_ERROR / PILL_INK_SUCCESS) — pre-existing AA misses on the same row.** These are outside this diff, measured in light at 10px: "Failed" pill 3.98:1, "Sent" pill 3.70:1. The governed "Not sent" pill already got the same ink mix (`ClientsConversations.tsx:283-286`). Proposed fix: apply `text-[color-mix(in_oklab,hsl(var(--destructive))_62%,hsl(var(--foreground)))]` to the plain Failed pill at :152, and the equivalent `--success` mix to Sent at :161. Dark passes: 5.90 and 6.77.

It derives from the semantic `--warning` token, so it is within §11. The meaning stays legible by its label, and the act gold remains the only filled gold.
