# UI delivery evidence: EXP03 approve now, send later — a scheduled governed email in the inbox, cancellable through the door

Branch `claude/great-heisenberg-u7kyd9`, commits f2198620 (feature), cd41c069 and d26b90f3 (review fixes), plus a4662e29 (the craft fixes from this record's first render). Four UI files change — `src/pages/admin/ClientsConversations.tsx`, `src/pages/admin/conversations/ThreadRow.tsx`, `src/pages/admin/conversations/governedSend.ts`, `src/components/chat/confirmPreview.ts` — and the backend (migration 20271119000000, comms-email-command, send-message, comms-scheduled-drain, the shared comms-email adapter/contract) declares `Visible-Flow-Impact: yes`.

What a person sees change in Clients → Conversations:

- **An approved email set to go out later** shows a neutral **Scheduled** pill and, under the body, one row: **"Sends <weekday, month day, time in the viewer's clock>"** (never split across lines) and a separate **Cancel** button (accessible name "Cancel the email scheduled for <time>"). Cancel goes to the governed email door (`comms-email-command` with exactly `{ expected_tenant_id, operation_id, cancel: true }`), never the generic undo, which no longer touches a governed row.
- **While the cancel is on its way** the button reads **"Canceling…"**, is disabled and `aria-busy`; a second click does not reach the door again.
- **The door's answer is a toast:** "Canceled — it won't be sent." (success); "Already canceled — it won't be sent." and "It didn't go out." (plain toasts — nothing going out is what the owner asked for); "Too late — it's already on its way." and "Couldn't cancel it. Refresh the conversation to see where it stands." (error toasts). The thread then re-reads the row and keyboard focus moves to the reply box.
- **A cancelled email** reads a neutral **Canceled** pill + "Canceled — it won't be sent.".
- **Past its 15-minute release grace** (or refused at release) the email reads **Not sent** with one owner-language line (`governedNotSentLine`), one per reason: unsubscribed/bounced, no consent, do-not-contact, no unsubscribe link, a generic hold, a changed address, lost access, or "Nothing went out." No code reaches the screen.
- **The thread list** shows "Scheduled · in about …" only while the row truly is scheduled (`isScheduledMessage`): a governed row past its grace still reads `queued` in the database but is no longer listed as scheduled.
- **The approval card** (`confirmPreview.ts`) carries the send time when one is set (parse only; the card that shows it is not rendered by this record).

§13: no product control creates a scheduled governed email yet (the composer switch is the next slice), so every state above is reachable today only by data. The frames render them from data shaped exactly as the migration writes it.

## User job and state map

The owner approves an email to a client to go out later and keeps an eye on it in the thread. The scroll owner is the thread column; the list column scrolls on its own.

- **Scheduled:** neutral pill; "Sends <local time>" and a Cancel button under the body; the list row shows "Scheduled · in <distance>".
- **Cancelling:** the button reads "Canceling…", disabled and `aria-busy`; nothing else changes until the door answers.
- **Cancelled:** success toast; Canceled pill + "Canceled — it won't be sent."; list marker gone; focus to the reply box.
- **Too late:** error toast "Too late — it's already on its way."; the row reads Sending…; then whatever the send records.
- **Already cancelled:** plain toast; Canceled. **Closed otherwise:** plain toast "It didn't go out."; Not sent + its line.
- **No readable answer:** error toast; the row stays Scheduled; Cancel works again.
- **Past grace / refused at release:** Not sent + one owner-language line; not listed as Scheduled.
