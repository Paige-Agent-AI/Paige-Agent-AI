# Vibe Studio planning handoff

The owner approved the centered In Progress conversation and requested it in the existing Solo Studio. The main Studio prompt creates one original project. It opens NEXUS planning in that project's native chat thread. Approval of the current saved plan reveals the existing Project Conversation, canvas and timeline in place.

- A planning turn can ask a question or return a plan. It cannot invoke artifact or publishing tools. The saved plan is read back before its approval appears.
- The first build claims the exact current plan inside the existing thread. The build uses only the original private creative tools and retains their native authority checks. The existing Publish door remains separate.
- The project's creation-time enrollment survives interruption before the first chat turn and legacy transcript edits. An authorized teammate or a returning owner can open existing artifacts with their own thread. A pending build check reads the original conversation and manifest without replaying effects.
- The same conversation component stays mounted when the layout changes. Motion uses a short translation and opacity change. Reduced motion keeps the handoff immediate and focus returns to the composer.

This change applies to the shared eligible Solo path. Fixtures in the Studio render and planning tests use synthetic data. Deployment and authenticated acceptance require the normal PAIGE Cloud and Supabase release readbacks and a signed-in Solo walkthrough.
