## User job and state map

- Purpose and audience: active teammates of one canonical SOLO workspace talk in channels, DMs and threads. Primary action: read and post. Act moments: Create channel, Add N people.
- Layout follows the hub's own width (`container: th-hub / inline-size`): three columns with an inline thread at ≥1150px, an overlay drawer below 1150px (the conversation under it is inert), one column with a back button below 760px (the drawer covers everything; list and conversation are inert). The script mirrors both thresholds.
- Unread integrity: mark-read runs when a conversation is opened into view, when a narrow hub's conversation view comes on screen, when a phone thread closes back onto the stream, or on a refresh while the stream is on screen; each call names the newest top-level message held for display (`p_through_message_id`, A8). The phone list view and a phone thread never mark the stream read.
- Refresh: the newest page is joined to what is held; if it has more behind it and is entirely newer, it replaces the held list (keeping anything newer, such as a message just sent) and "Load earlier messages" / "Show earlier replies" is offered. New messages and replies by others are announced as a count by the hub's single live region; the stream is a labelled region, not a log.
- Exits: back to the list; Settings → Team (owner or admin first use); reload on scope_changed.
- Scroll owners: the conversations list, the message stream and the thread body, each inside a full-height host.

## Review and limitations

Round-3 verifier findings addressed: a refresh after a long absence could join a newest page to an older held list and leave a silent hole (now replaced and earlier messages offered, stream and thread); the stream was a role=log live region announcing every message alongside the hub's live region (now a labelled region; arrivals are a count); the thread's window-level Esc listener let the shell's Esc fold PAIGE (now handled inside React and marked handled); mark-read did not name what was displayed (A8); a phone thread over the stream still counted as on screen; separator text was not exposed; panes under the drawer stayed reachable; a private channel left in one click with no word about losing access or archiving; the pressed visibility toggle had no selection mark beyond colour; a first `unavailable` settled without re-reading a possibly stale workspace context.

Round-2 fixes stand: container queries for the PAIGE-narrowed hub; phone first use in the list view; 40px targets; neutral Add people toggle with a gold submit; stacked create-channel actions in the narrow column; refusals announced once; unread digits plus screen-reader words; visibility as aria-pressed toggles; no "?" member count; gold text tokens; the zero-specificity button reset.

Limitations: every item in UNVERIFIED above. The harness frame is not the tenant shell, so the shell's own chrome, PAIGE content, command row and Esc handler are placeholders or stand-ins, and none of these frames or drives is authenticated runtime proof.
