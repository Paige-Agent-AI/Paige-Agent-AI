## Affected-flow and collision packet

Actor: authenticated Solo owner/admin. Goal: authorize a saved external tool and return to its
canonical Integrations record without claiming readiness before verification.

1. Integrations → create credential-free shell → explicit sign-in → provider consent → callback
   → Integrations. Server-owned PKCE state selects routing, actor, tenant, generation and scopes.
   Browser/query account identity never supplies authority.
2. Cancel, expiry, exchange failure, revoked membership, disabled/rekeyed connection or newer
   consent: fail closed. Known valid return context gives a safe recovery route; invalid state
   has one uniform public refusal. No raw provider prose or credentials enter return URLs.
3. Return opens only a record from the active account's canonical read. An absent record stays
   unavailable. Read failure retains the navigation hint for explicit retry. Return never starts
   verify, sign-in, creation or execution automatically.
4. Cancelled first-use `none` shell offers explicit same-record Sign in when the saved canonical
   row is enabled/configured generic HTTP MCP and the actor can manage it. No duplicate create.
5. Close/Escape returns focus to the saved tool tile. Effect replay cannot erase the same-scope
   returned drawer. Loading/user/tenant changes synchronously mask and clear old context;
   late prior-account reads cannot reopen it.
6. Existing agency/sub_account shared callback routes remain Connections; no new non-Solo
   route or setup surface is created. Specialized n8n REST remains refused by generic OAuth.

Dependencies consumed: existing tenant context, `useMcpGateway`, canonical routing, encrypted
OAuth state, `_mcp_caller_capabilities`, existing membership and connection generation guards,
real SoloSettings/Integrations components, existing drawer and shell CSS. No new authority store,
