## Review and limitations

Independent review ran on the pushed diff (1a9c5d0). Every blocking finding is fixed in this PR.

- **Adversarial verifier (§39): FIX-FIRST, now fixed.**
  - (high) Saving work details reloads the roster; for one frame the roster is empty and the dialog unmounted, discarding unsaved contact edits. The dialog now reports unsaved contact edits and the parent holds it open across the reload, as it already does for an in-flight removal (regression test above).
  - (high) Clearing or changing the representative kept the previous person's phone, hidden but saved, in Setup and in the A2P record. Changing the representative now clears it.
  - (medium, §58) The picker had dropped the source badge and the Adopt / Override choice for a connection-sourced number. Both are back on the picker.
  - From its plausible list: focus no longer falls to the page when the save button leaves after a save (it moves to the outcome, which is also announced); the picker is a div radiogroup (no broken list semantics) with its error tied by aria-describedby; re-choosing an already-checked number stored with spaces now stores it in E.164.
- **Compliance officer (§5): four blockers, now fixed.**
  - "Changed under Security" was false: no screen changes a sign-in email. The plate now says "Used to sign in. Nothing on this screen changes it."
  - The editor's client copy promised that Paige sends to and recognises a team member's addresses; neither exists for users. The editor takes an audience and, for a person, says only which address is primary.
  - The missing Adopt / Override choice (as above).
  - Closing with only contact edits pending said "Close". It now says "Cancel", as it does for work details.
  - Taken from its non-blocking list: no gold save button at rest; the dialog description names contact details; the A2P record's picker label matches its siblings; the representative change no longer carries a number across; PAIGE_OPEN frames that match their closed frames now say why.

Recorded, not fixed here:
- `set_user_contact_methods` replaces a person's whole list with no version check, so two editors saving at once can lose the earlier save's addition. This is a contract change, for a later PR.
- The migration lets an admin of workspace A rewrite the contact list of a member who owns workspace B, because a user's contact list is global rather than per workspace. The "an admin cannot edit the owner" rule only checks the current workspace. This needs an owner ruling.
- The Team roster rows still show the sign-in email, so nothing on the roster says your own row holds your contact details (§36).
- The picker's "add it under Team" link leaves Setup without the unsaved-changes guard.
- The AA contrast of the small faint captions in the dialog was not measured.
- The old admin MemberProfileDrawer still edits profiles.work_email/phone as single values; the dependents pass moves it.
