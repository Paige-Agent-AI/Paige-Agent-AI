## Review fixes (PR #1699)

Built on b617cbe9b (the real door and Migrations E/F), reading growth-publish-command/contract.ts and door.ts for the exact codes; the door was not edited.

1. Optional checks rendered as blocking: readPreview now carries the door's `blocking` flag (absent → blocking), and an unmet non-blocking check (asks_email, routes_to_pipeline, alert_email, thank_you) shows the neutral Circle labelled "Optional" again, as on main. Frame: state-optional-1366x768.png.
2. The off state named the wrong act: only publishing being off replaces the panel. With only unpublishing off, a live piece keeps "This is live", Unpublish is disabled and the line where it sits says unpublishing is switched off; Publish again stays. Frame: state-unpublish-off-1366x768.png (live form); the funnel case is a rendered test.
3. Refusal mapping: forbidden carries the door's reason — NO_WORKSPACE → "Open this workspace first", OTHER_WORKSPACE → "This piece belongs to another workspace", NOT_ADMIN → "Only an owner or admin can publish". Redeem replies where nothing ran become PublishNotDone ("Nothing changed", Try again), not "may not be live". Frames: state-notdone-1366x768.png, state-no-workspace-1366x768.png.
4. Stuck on a stale approval: the once-per-panel `retried` guard is gone. Every refused click gets one fresh prepare and the next click redeems the new fingerprint; a not-done or unverified redeem disarms the fingerprint and the button re-prepares. Nothing redeems without a click.
